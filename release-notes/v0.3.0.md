# mcp-gitee-ent v0.3.0

本版本新增渐进式工具发现与企业测试、项目协作工具，并统一参数命名、修正 Gitee API 契约及多处返回结构。

## Highlights
- 新增 `search_tools`、`inspect_tool`、`invoke_tool` 三个渐进式工具发现元工具，支持按自然语言搜索工具、查看完整参数 schema 并调用已启用工具。
- 新增测试管理工具：测试用例、测试模块、测试计划、测试报告，以及批量执行测试计划用例的 `execute_test_plan_cases`。
- 新增检查门禁工具：`list_pr_check_runs`、`list_commit_check_runs`、`list_project_check_runs`、`get_check_run_annotations`。
- 新增企业查询与协作工具：`list_baselines`、`get_baseline`、`list_common_views`、`list_workloads`、`get_program_overview`、`list_group_members`、`get_member`、`list_group_projects`、`search_documents`、`list_recent_documents`、`list_issue_attachments`、`list_issue_authorizations`、`set_issue_starred`、`link_issue_document`、`unlink_issue_document`、`restore_issues`。
- 新增删除工具：`delete_label`、`delete_milestone`、`delete_scrum_sprint`、`delete_enterprise_document`、`delete_enterprise_document_page`。
- 创建 PR 支持 `pr_assign_num`、`pr_test_num`；工作项操作支持使用数字 ID 或 ident。
- 新增 Webhook 工具，并将默认 scope 设为 all。

## Improvements
- 测试管理 API 对齐：`create_test_case`、`create_test_case_in_plan` 必须提供 `case_steps`，步骤必须包含描述；`create_test_report` 必须提供 `components`；无已批准版本时引导使用 `create_test_case_in_plan`。
- 测试用例执行改为 `execute_test_plan_cases`，底层使用 `batch_execute`。
- 工作项文档关联契约修正：统一 `doc_node_id`、`doc_id`、`get_issue_development_links(type=docs).id` 与 `doc_nodes.id` 的语义；`document_id`、`info_id`、`page_id` 会被拒绝。
- `unlink_issue_document` 直接返回剩余关联文档与 `is_linked`，无需额外读取。
- `get_document_node` 的 `linked_issues_count` 数组更名为 `linked_issues`，并新增 `linked_issues_total`。
- 附件接口会先将工作项 ident 解析为数字 ID，再调用仅接受数字 ID 的 Gitee API。
- 看板列和测试用例模块树返回 `{data,total_count}`；空检查运行列表规范化为空数据。
- 写工具无响应体时返回 `{ok:true,...}` 确认，并处理 `add_test_cases` 的 204 响应。
- 标签颜色会规范化为 Gitee API 可接受的形式。
- 创建迭代后会重新读取，创建者可直接看到解析后的负责人。
- 补充渐进式发现、测试计划状态流转、文档/成员标识语义和基线可用性说明。

## Fixes
- 修复测试管理、工作项文档关联、PR 参数、看板/模块树返回结构等与 Gitee API 不一致的问题。
- 修复工作项测试用例解除关联需逐个 ID 调用的问题。
- 修复工作项附件、检查运行空列表、204 响应等边界情况。

## Security
- 渐进式发现工具调用受 `ENABLED_TOOLSETS`/`DISABLED_TOOLSETS` 和请求级过滤约束：禁用或不可见工具不会被搜索返回，也不能被 `inspect_tool`/`invoke_tool` 调用。
- 显式 `ENABLED_TOOLSETS` 条目优先于同名 `DISABLED_TOOLSETS` 条目；发现元工具在白名单下仍可用，除非被显式禁用。
- 工具目录提供风险等级、只读、幂等和二次验证元数据，需二次验证的工具不可通过 `invoke_tool` 调用。

## Upgrade Notes
- 破坏性变更：`list_kanban_columns` 和 `get_test_case_module_tree` 现在返回 `{data,total_count}`，不再返回裸数组。
- 破坏性变更：`create_test_case` 和 `create_test_case_in_plan` 现在必须提供 `case_steps`，且每个步骤需有描述。
- PR 工具参数 `pull_request_id` 重命名为 `pull_request_iid`；`pull_request_id` 表示内部数据库 ID。
- 参数规范化：`repository_id` 替代 `project_id`，可传仓库 ID 或仓库路径；`program_id` 专指 Gitee Program（项目）。`state`、`status`、`priority`、`assignee_id`、`issue_id` 等改为 `state_id`、`statuses`、`priorities`、`assignee_ids`、`linked_issue_id` 等规范名，旧参数会被拒绝并给出迁移提示。
- `create_test_report` 现在必须提供 `components`。
- `get_document_node` 的 `linked_issues_count` 已更名为 `linked_issues`，总数使用 `linked_issues_total`。
- `unlink_issue_document` 返回剩余关联文档与 `is_linked`，无需再额外读取。
